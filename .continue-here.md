## 2. Completed This Session
1. **TTS Latency & Double-Voice Bug Resolution:**
   - **Root Cause Identified:** 
     1) `VoiceModeOverlay` was listening to `isStreaming` and auto-initiating cloud TTS generation in the background even when closed.
     2) `InlineAudioPlayer` used uncoordinated local hook instances without in-flight request cancellation, allowing overlapping TTS requests to play simultaneously after a 14-second network delay.
     3) Gemini TTS was receiving raw, uncleaned markdown tables and formatting, causing ~14.3s generation latency.
   - **Fix Implemented:**
     - Created `frontend/src/store/voiceStore.ts` as a centralized singleton audio coordinator:
       - Enforces exactly ONE audio stream at any time.
       - Immediately aborts in-flight fetch requests via `AbortController` and halts active playback when a new speech or stop action is requested.
       - Added **Instant Voice (<100ms)** via browser `speechSynthesis` as the default zero-latency engine, with 1-click toggle to **Gemini HD** neural voice.
       - Added dynamic loading states (`Buffering...` spinner) on the player button to prevent duplicate clicks.
     - Guarded `VoiceModeOverlay.tsx` with `if (!isVoiceModeOpen) return;` so it strictly never speaks during normal chat.
     - Cleaned markdown and optimized chunk boundaries in `backend/app/services/tts.py` to prevent lengthy generation spikes.
2. **Automated Testing & End-to-End Verification:**
   - Live browser subagent validation:
     - Confirmed instant zero-latency speech start on click.
     - Verified clean stop button behavior.
     - Verified subsequent playback has strictly **single voice (zero echo / zero double voice)**.
     - Verified interactive mode toggle between **Instant** and **Gemini HD**.
   - Pytest suite: **14 / 14 passed** in `backend/tests/`.
